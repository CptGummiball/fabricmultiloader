# Code of Conduct

## The short version

Be decent. Assume good faith. Criticise work, not people.

## Expected behaviour

* Be respectful of differing viewpoints, experience levels and native languages. Not everyone here
  writes English as a first language, and technical precision matters more than grammar.
* Give feedback on the substance: what is wrong, why it matters, what would be better. "This is
  broken" helps nobody; "this breaks on Java 17 because the class file major is 61" does.
* Accept feedback the same way. A rejected patch is not a rejected person.
* Respect the maintainer's right to say no. A project that accepts everything becomes maintainable
  by nobody.

## Unacceptable behaviour

* Harassment, insults, or personal or political attacks
* Discriminatory language or imagery of any kind
* Publishing someone's private information without permission
* Deliberately derailing discussions or reopening settled decisions without new arguments
* Reporting security issues publicly to pressure a faster fix — see [SECURITY.md](SECURITY.md)

## Scope

This applies in issues, pull requests, discussions, commit messages and any other project space,
and to anyone acting as a representative of the project in public.

## Enforcement

Report problems to **treeman1992@outlook.de**. Reports are handled confidentially.

Responses are proportionate: a private word first, then a warning, then a temporary or permanent
ban from project spaces. The maintainer decides, and will explain the reasoning to the person
affected.
